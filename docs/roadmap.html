JobMatcher AI implementation roadmap

The brief is solid: clear MVP definition, strong ethics rules, and a sensible open-source stack. Its main risk is size. It describes seven modules, eight extra features, fifteen pages and eighteen entities. This plan builds the ten Definition-of-Done items first as thin vertical slices. Each milestone ends with something you can run and demo. Tests and CI start in week one instead of waiting for Phase 8.

Analysis

Technical risks and gaps in the brief

Ranked by how much each could derail the MVP. Each has a mitigation that is built in from the milestone where it first appears.

RiskSeverityWhy it mattersMitigation
Job source accessHighLinkedIn, Indeed and Welcome to the Jungle have no permitted public API, and their terms forbid scraping. The Indeed publisher API is gone.API and feed first: France Travail, Adzuna, Arbeitnow, and the public job-board APIs of Greenhouse, Lever and Ashby. Pages submitted by URL are parsed through schema.org JobPosting JSON-LD. Each source's terms are recorded in docs/sources.md.
Fabricated contentHighA local 8B model will invent metrics, employers or company facts in letters and CV rewrites.Evidence-grounded generation. The model returns claims that each cite CV fact IDs, and a validator drops any claim without a source. The UI shows the evidence, and the user approves every change.
Prompt injectionHighJob ads and CVs are untrusted text that goes straight into prompts.The LLM has no tools and no network access. Untrusted text sits in delimited data blocks, and output must match a JSON schema. Contacts are never taken from LLM output, only from regex matches on the source text.
License contaminationMediumPyMuPDF is AGPL-3.0. Llama models use a custom license. Qwen2.5-3B uses a research license. spaCy pipeline licenses vary by language.Use Apache Tika for PDF and DOCX, plus Tesseract for OCR. The default model is Apache-2.0 (Qwen3). A license check in CI fails the build on disallowed licenses, and THIRD_PARTY.md is generated.
Local inference speedMediumA 7–8B model on CPU can take 30 to 120 seconds per letter.Generation runs as background jobs with progress shown in the UI. A smaller model can be selected, and an OpenAI-compatible provider is optional. Tests use a deterministic mock.
Personal data (GDPR)MediumCVs and recruiter names are personal data.CV text is encrypted with AES-GCM at the column level. Users get retention settings, JSON export, and CV or account deletion. Logs contain no PII. Recruiter names are stored only when the official source publishes them.
Multilingual skillsMedium"Développeur Java", "Java developer" and "J2EE" need to resolve to the same skill.A curated alias dictionary in French and English is seeded through Flyway. The ESCO taxonomy (EU, multilingual) can be added later. Embeddings catch the rest.
Scope creepMedium15 pages, 18 entities and 8 extra features compete with the MVP for time.Extra features (§11) only start after v0.1. No page ships before its backend works, which the brief already requires.
Score misreadLowUsers may read a score of 82 as an 82% chance of getting hired.A coverage indicator shows how much of the score is based on known data. The wording says "compatibility", never "probability".

Where I deviate from the brief

  • Tests and CI from M0, not Phase 8. Every milestone ships with its own tests.
  • Karma → the current Angular test runner (Vitest). Karma has been deprecated since 2023.
  • No PyMuPDF. Its AGPL license conflicts with a permissive project license. Tika covers the same needs.
  • Playwright scraping comes after the MVP. JS-rendered career pages are rarely needed once ATS APIs are covered.

Ambiguities, resolved by default

  • "Recruiter profiles": link out to them, never scrape them. LinkedIn's terms forbid scraping.
  • Company news: no free, licensed news API exists. Company intelligence uses the company's own site and Wikidata, with citations.
  • Unknown salary under a salary filter: a toggle controls whether to include offers with an unknown salary. It is on by default.
  • Job offers are a shared catalog. Matches, documents and applications belong to each user.

Milestones and exit criteria

M0 · Foundation

wk 1–2
  • Monorepo: backend/, frontend/, nlp-worker/, e2e/, infra/, docs/
  • Docker Compose: postgres+pgvector, api, web (nginx), and Ollama plus the worker behind the ai profile
  • Flyway V1 baseline with audit columns; RFC 9457 error responses; springdoc OpenAPI

  • GitHub Actions: Gradle test with Testcontainers, Angular lint/test/build, license check

Exit: docker compose up opens the app shell. The status page shows "DB ok · AI: ollama unreachable, using none" when Ollama is off, and CI passes.

M1 · Identity & CV

wk 3–4

  • Upload PDF/DOCX ≤ 10 MB: Tika magic-byte check, reject macros and encrypted files, parse timeout, OCR fallback

  • CV versions, preferences (titles, seniority, remote, countries, visa, salary, contract)

  • Encrypted CV text; export my data; delete CV; delete account

Exit: a test user uploads a fixture CV, corrects one extracted field, runs the analysis and sees a ranked report. Another user gets 404 on that CV.

M2 · Job discovery

wk 5–6
  • JobSourceAdapter SPI + registry + health (last success, error rate, items per run)
  • Adapters: Arbeitnow (no key, zero-config demo), France Travail (OAuth), Greenhouse/Lever/Ashby boards, URL + JSON-LD

M3 · Matching

wk 7–8
  • Job-skill extraction with required vs preferred cues ("must", "required", "indispensable" / "nice to have", "un plus", "souhaité")
  • Deterministic score components in Java, weights configurable, renormalized over known data

M4 · Letters, contacts, email

wk 9–10
  • Detect the offer's language (Lingua), FR/EN templates, language selectable per document

Module 3 design

Explainable scoring

score = 100 × Σ wᵢ·sᵢ / Σ wᵢ
  over components i where both sides are known
coverage = Σ wᵢ(known) / Σ wᵢ(all)

Each component sᵢ is between 0 and 1 and comes with its own evidence list. When a component is unknown, for example because the offer gives no salary, it is dropped from both sums. It is never counted as zero. That is how "missing information is not a negative" is implemented.

Hard constraints, such as a missing work authorization or an on-site role in another country with relocation turned off, are shown as blockers next to the score. They are not hidden inside it. Protected characteristics never enter the model.

Decisions to confirm before M0

  • Project license: Apache-2.0 (proposed) or AGPL-3.0, which would also allow PyMuPDF and forces hosted forks to share their changes.
  • Target market: France first (France Travail) is assumed. Other markets change the source priority.
  • Hardware: GPU available? That decides between qwen3:8b and qwen3:4b as the default.
  • Build tool: Gradle (proposed) or Maven.
